# ChrysaLisp 7.9

## Install

*	`snapshot.zip` made again, of 170,785 bytes: Lisp binds the natives
	of `:bytes`, `:shorts` and `:ints` as it starts, and the VP64 image
	of an install has to hold them. An install from the old one stops at
	the first of them.

*	A new `snapshot.zip`, its VP64 boot image and Windows host as they
	were, and beside the image `obj/vp64/VP64/sys/trans_id`, the id of the
	translator it holds. Only a make of an image writes that, and an
	install unzips the VP64 image and makes none, so after one an
	emulated node trusted none of the code the install had kept for it:
	"The code kept for this boot image is of another translator" at each
	start, every function made again as it was bound, till a `make all
	boot`. `tests/system/test_snapshot.lisp` checks the id is there, and
	is the tree's when the image is.

*	An install with a file in the tree bigger than a string may be, one
	`.gitignore` does not leave out, hung at its end: the waypoint hashes
	every file, and read each whole. A file bigger than a megabyte is
	hashed a piece at a time, (sync-file-hash), so one of any size is had.

*	The XML parser reads XML 1.0 as it is written, still in one pass in
	VP, `lib/xml/lisp.vp`, now knowing where in the document it is: text
	is given whole, as it is, where it was split into words, and a word
	with `-`, `/`, `?`, `=` or a quote in it became markup and stopped

	`(xml-entities)`. `XML-parse`'s callbacks are as they were, the Lisp

*	Gradients on a canvas: `(. canvas :set_linear x y x1 y1 stops
	[spread])`, t 0 at x y and 1 at x1 y1, and `(. canvas :set_radial cx
	cy r stops [spread])`, in the pixels `:fpoly` draws in. Every fill
	after it is of it, shapes and glyphs by `:fpoly`, boxes by `:fbox`,
	till `:set_color` puts the solid color back. The stops, `((offset
	argb) ...)`, are 256 colors, each channel mixed straight between the
	stops either side and not premultiplied, offsets kept to 0 to 1 and in
	order as SVG has them; the spread is `+spread_pad`, `+spread_reflect`
	or `+spread_repeat`. A linear gradient is exact: each run's first
	pixel is worked out from integers of the fixed inputs, its step of the
	256 carried along by quotient and remainder, as `:ftri` did its edges,
	nothing rounded and nothing drifting, a pixel 3000 along as exact as
	one at the corner. A radial carries its u so, its root `:sys_math
	:q_sqrt`, within one step. Antialiasing is `:fpoly`'s as before, and a
	gradient of one color draws what that color does to the byte. A child
	of a farm of strips sets a paint on its own canvas of the shared
	pixels. `tests/system/test_paint.lisp`.

*	The gradients take a matrix: `(. canvas :set_linear x y x1 y1 stops
	[spread m])` and `(. canvas :set_radial cx cy r stops [spread m])`, m
	a mat3x2 from the space they are given in to the canvas's pixels, as
	an SVG's is, under which a linear's bands lie at a slant to its line
	and a radial is an ellipse. Both spans are one form: two rows of a
	matrix from a pixel to the gradient's own space, 32 bits of fraction,
	worked out again for the first pixel of every run and stepped along
	it, the inverse made once in doubles. A linear is no longer exact to
	the integer but within one step of the 256, a straight ramp still
	exact; 8% quicker, the radial 7% slower.

*	`push` into an array of numbers or a raw array takes what has raw

## VP

*	A block of memory may be as big as 256 MB, was 64: a large picture
	could not be loaded whole.

*	Raw data has methods: `:seq :get_raw`, where a sequence's bytes are,
	how many elements and how wide, none of a list; `:array :push_raw`,
	raw bytes onto an array in whole elements of its own; `:array
	:copy_raw`, a copy that takes the elements last first, the one place
	a reversed slice or splice is done. `push`, `obj-set` and `buf-set`
	are made of them, and `slice`, `cat`, `append` and `splice` of every
	array copy by `:sys_mem :copy`, which moves a `bytes`, a `shorts`, an
	`ints` or a `floats` a long at a time: a slice or a push of 4096
	`bytes` 6 times quicker, of `floats` twice. `:sys_mem :copy` asks if
	both ends and the length are whole longs in one test, not three. The
	`push` binding finds what each argument is by one walk back along its
	classes, which is the check of it too, with no `:inst_of`: six numbers
	into a `nums` 26% quicker, a list as it was. `make test` as it was.

*	`(n2i)`, `(n2q)`, `(n2d)` and `(n2f)` check their argument as they
	dispatch on it, a walk up the ladder of the number classes from
	`:float` to `:num`, not a signature check and then the dispatch; the
	one that hands back what it is given exits there and then, and a
	conversion's answer goes straight to where it is returned. A
	conversion 6% quicker, one that hands back what it is given 7%.

*	`(elem-set)` checks its array as it dispatches on it, one walk back
	along its classes, a list to hold a ref, any other array raw, and its
	value as it is put in, a number its value; not a signature check and
	two `:inst_of`, the one for a list walking the whole chain of every
	number vector to find it is not one. Nothing kept on the stack. A set
	into a `nums`, `fixeds`, `doubles`, `floats` or `bytes` 16% to 20%
	quicker, into a list 5%.

	of it, `+canvas_span`, with `+canvas_span_data` its own: `:fpoly`,
	`:fbox` and `:span` call through it, `:span_noclip` unless a paint is
